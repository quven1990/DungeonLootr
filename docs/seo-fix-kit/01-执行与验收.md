# 执行边界与技术验收

基线日期：2026-09-07。材料来自公开页面抽查，不是全站源代码审计，也不代表 Google 内部判断。站点可能已修改；先核对代码和现状，已经修好的不重复修改。

## 工作方式
1. 读取仓库已有 AGENTS.md、README、package.json 和部署配置，尊重既有规则与用户未提交改动。
2. 用 rg 找页面路由、内容数据、模板、metadata、robots、sitemap 生成器。不预设 Next.js/Astro 等技术栈。
3. 创建 docs/seo-remediation-report.md，逐项记录“原问题、代码位置、修改、验证、待人工事项”。
4. 先完成确定且可逆的代码与文案修复，再处理依赖游戏证据的内容。不要只提交计划。
5. 无实测资料时，不编造职业、数值、掉率、版本、作者经历、实测次数、兑换成功或 Google 收录状态。改成准确标题、缩小范围，或合并确实重复的薄内容。
6. 不默认删除页面或给所有待核查页面加 noindex。对尚无独立答案的草稿逐页决定：补实、合并（必要时301）、或临时noindex并移出sitemap。补实后恢复可索引。
7. 不自动更换域名、重构框架、批量改URL、删除工具、关闭Cloudflare/WAF或部署生产。当前任务是产出本地可审查修改；用户另有部署授权时遵循其授权。
8. 缺少 GSC、Cloudflare 或实玩权限不妨碍继续其他修复；最后列出具体缺口，不假装已完成。

## 技术核查（待核实，不是已证实故障）
- 此前审查环境对两个首页及真实 sitemap 请求均遇到403；搜索工具可读取部分正文。这不能证明Googlebot遭拦。不要通过伪造Googlebot UA就宣布Google访问正常。
- 源HTML与渲染后正文：主要标题、答案、表格及真实a[href]内链可读；不是仅空壳或必须点击才能加载。
- 每个应收录页：200、无意外meta robots/googlebot noindex或X-Robots-Tag noindex；canonical为正确绝对URL，不全指首页。
- HTTP/HTTPS、www/非www、尾斜杠：选择项目现有规范；重复入口一致重定向或正确canonical；不制造重定向循环。
- sitemap：用本包指定实际路径，XML合法、URL绝对且同站、无重复、无fragment；只收200且可索引的规范页面。不要把robots或key文件当内容URL。
- sitemap lastmod只随页面实质改变更新，不能每次构建全站刷当天；缺可靠时间可省略。
- robots.txt保留既有指令，添加正确Sitemap声明，Googlebot可访问正文及必要资源。Google-Extended与Googlebot不同；禁止前者不是Google搜索禁令。
- 缺失页面返回真实404；不要所有随机路径都200回首页。
- Title/description与该页实际答案匹配；H1描述主题；不要泛化关键词堆砌。
- 结构化数据与可见内容一致，不虚构评分、作者或日期，不为获得展示胡加FAQ/HowTo标记。
- 移动端检查表格溢出、导航遮挡、按钮可操作、布局位移。重复的移动/桌面表格先检查CSS展示再处理，不能仅因提取文本重复就断言SEO处罚。
- 视频与图片：有实际内容用途，视频保留来源、可核实时间点；控制第三方资源、明确尺寸，非首屏资源按需加载。没有测速证据，不宣称性能合格。

## 必须执行的验证
- 运行仓库已有且与改动相关的构建、类型检查、lint；无现成命令如实记录。无需为文字修改添加镜像测试。
- 检查代表性首页/攻略/工具/未发布页/不存在路径的状态、canonical、robots和正文。
- 检查实际 sitemap生成输出与发布策略，无noindex URL混入。
- 工具修改需测正常输入、0、负数、非法输入和边界值；区分“未验证玩法参数”和“数学公式有效”。
- GSC人工验证：各站首页和一篇核心攻略做URL检查→测试实际网址→看HTML/截图；看正式索引状态及Google选择canonical；Sitemaps显示成功。实时可访问不等于已收录。
- 403仍存在时记录URL、时间、响应；由站主查Cloudflare对应安全事件和已验证爬虫访问日志。仅调整造成误拦的规则，不全关防护。
- 不把IndexNow提交当Google收录证明，不承诺多少天收录或排名提升。

## 最终交付格式
- 已改：问题ID、文件、效果。
- 已验：命令/页面、结果。
- 待核：谁需要提供什么（例如重置确认截图、GSC抓取结果）。
- 风险与回滚：仅实际存在的风险；保留diff可审查。
